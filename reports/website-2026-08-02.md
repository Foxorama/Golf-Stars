## Where the work is

**The site is a separate repository at `C:\vulpecula-site`** — a local git repo with one commit,
not pushed anywhere. Nothing has been deployed and no DNS has been touched.

It is deliberately **not** a folder in this repo. The settled web architecture (recorded in the
project notes on 2026-07-30) is that `vulpecula.games` is a STUDIO site with one page per game,
and this repo is one game. Coupling them would mean the studio site could only be edited by
touching the game's history, and a second game would have nowhere to go.

```
C:\vulpecula-site\
  index.html                  the studio landing page
  far-carry/index.html        the game's page
  far-carry/guide/index.html  "How to play" — the guide the game links out to
  404.html
  assets/css/site.css         the whole stylesheet
  assets/js/sky.js            seeded starfield, drawn in a canvas (no image file)
  assets/js/toc.js            guide contents highlighting
  assets/img/                 favicon, two social cards, 12 screenshots (1.8 MB total)
  scripts/og.mjs              composes the studio social card (optional)
  _headers  _redirects        Cloudflare Pages config
  robots.txt  sitemap.xml
  README.md                   what's there, house rules
  DEPLOY.md                   ← READ THIS BEFORE DEPLOYING
```

`DEPLOY.md` is the real document. It carries the Cloudflare Pages setup step by step, the
output-directory trap that already cost this project one green-but-broken staging deploy, the DNS
note about why `farcarry.vulpecula.games` must stay DNS-only, and the recipes for re-making every
image.

## Decisions taken, and why

**Plain static HTML, no build step, no dependencies.** Not laziness. A site with a build has a way
to deploy green while serving the wrong thing — which is exactly how the game's own staging
environment failed the first time — and a marketing site that can be fixed by editing one file will
still be fixable in five years. The cost is a duplicated header and footer across four pages, which
is the right trade at four pages and the wrong one at ten.

**Cloudflare Pages, not GitHub Pages.** DNS for `vulpecula.games` is already on Cloudflare, so the
apex works without the CNAME-at-the-root problem, and `_headers`/`_redirects` give a static site
real CSP and redirect rules with no server.

**The game stays on its own origin, and this is not negotiable.** A PWA binds to its origin and
`localStorage` is per-origin, so serving the game from a path on the studio site would be a
different origin as far as every browser is concerned: new install, empty save, no way back except
the export file. Separately, the itch.io widget is a third-party cookie-setting iframe — fine on the
studio site, never on the game's origin, where `PRIVACY.md`'s claim is guarded by a scan that would
stay green while the claim went false.

**Nothing loads from another origin.** No CDN, no web fonts, no analytics, no embeds. The CSP in
`_headers` states exactly that, so adding a third-party script would fail visibly rather than
quietly ship. The starfield background is drawn into a canvas from the sim's own `mulberry32`
rather than downloaded — the site keeps the game's "no asset files" promise for its own chrome.

**The palette, type stack and wordmark are the game's, copied not re-picked.** The tokens at the
top of `site.css` are this repo's `:root` values and the wordmark treatment is
`scripts/banner.mjs`'s, so the store banner, the title screen and the site read as one thing. If
the game's palette moves, move it there too.

## The guide, and the one link out of the game

The author's position, stated plainly: *in-game tutorials kinda suck; I just want to get into a
game and start playing.* So the guide is external and the game does not push it.

`far-carry/guide/` is ~15 sections: the swing gesture, the bag, reading a hole, putting, Stableford
and the cut, travel and fuel, which mode to start with, the golfers, caddies, what carries between
runs, the settings worth knowing, backups, installing, and troubleshooting. Every claim in it was
checked against the source rather than written from memory — the pull-to-power gesture from
`wireShotGesture`, the aim modes and toggles from `overlays.ts`'s own tables, the Stableford
formula from `score.ts`, the club sheet from `clubPicker.ts`, the endless allowance and the cut from
the CLAUDE.md invariants.

### The change on this branch

Branch **`guide-link`**, three files, full suite green (221 files / 2670 tests / 0 skipped):

- `src/brand.ts` — a new `GUIDE_URL`, alongside `GAME_TITLE`/`APP_VERSION`, because it is product
  identity and it ships inside builds that can never be edited again.
- `src/app/overlays.ts` — a `helpSection()` in the settings sheet: one row, `❔ Help`, between Aim
  assist and Save data.
- `index.html` — one CSS rule, `.gs-setrow--link`, so an `<a>` can wear the settings row.

Three things about it worth keeping:

- **It is the quietest surface available.** One row, in the sheet, below everything a player came
  there to change. Never offered, never prompted, never on a first run.
- **It is an anchor, not a button.** `target="_blank"` + `rel="noopener noreferrer"` is the whole
  mechanism — no reducer action, no dispatch, nothing in `backIntent`. `tests/privacy.test.ts` bans
  `fetch`/beacons/cookies, not links, so the "sends nothing" guarantee is untouched.
- **The URL is the SHORT path**, `vulpecula.games/guide`, which `_redirects` sends to
  `/far-carry/guide/`. A string shipped in an immutable build must not be a deep link.

Verified in a real browser against the built bundle: the row renders in the sheet with the right
`href`/`target`/`rel` and no underline, and at 320×568 on the largest text rung the sheet still
scrolls and the row is reachable.

> ⚠️ **Do not merge this branch until the site is live.** The link would 404. Everything else about
> it is finished.

## What needs a human

1. **Push the site repo somewhere and connect Cloudflare Pages.** `DEPLOY.md`, top to bottom. The
   only step with a trap in it is the build output directory — set it to `/`, and open the
   `.pages.dev` URL and *look at it* before touching DNS.
2. **Decide the contact address.** `index.html` currently points people at the itch.io comments and
   carries a `TODO` where an address would go. A personal address was deliberately not published.
   Cloudflare Email Routing gives `hello@vulpecula.games` free in about five minutes.
3. **Merge `guide-link` once the site answers.** Then the settings sheet has a working ❔ Help row.
4. **Read the guide for factual errors.** It was written against the source, but the author knows
   things the source does not say, and a wrong sentence on a help page is worse than a missing one.

## Not done, and deliberately

- **No itch.io widget yet.** It belongs on the studio site (it is fine there) but it is a
  third-party iframe, and adding it means opening `frame-src` in the CSP. Worth a decision rather
  than a default.
- **No devlog section.** Devlogs are on itch, which is where the reach is. If they ever want a
  canonical home, the site is ready for one.
- **No press kit, no newsletter, no social links.** The last is a standing preference, not an
  oversight.
