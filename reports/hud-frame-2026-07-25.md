# GS-hud-frame — one persistent play HUD, six states (2026-07-25)

Session report. Full design story: `docs/decisions/ui-intro.md` → *GS-hud-frame*. Rule: `CLAUDE.md`
→ UI layer → "ONE play HUD frame".

## The ask

From the Pixel 9a play-test: the play screen is laid out differently in each of its six view states.
Player's call, asked explicitly — **one persistent frame**, contents change, buttons never move or
disappear. Plus a permanent slot for the caddy, and bigger readouts.

## What shipped

- **`src/app/playFrame.ts`** — the ONE builder of the play screen's outer element. Five regions
  (info bar · nav column · caddy slot · controls panel · action column) mounted by every state.
- **Nothing removed, only disabled.** The nav column always ships five buttons; `»` and the commit
  button grey mid-flight rather than vanishing; the ⚙ is now reachable from the green.
- **Bottom-anchored panel, commit row last** — commit · caddy · `»` land at the same y in all six
  states even though the rows above differ in height. `»` is a fixed 46px box, not stretched.
- **The watch state gained a whole frame** — struck club, a carry bar in the power bar's slot, flight
  status, a greyed commit. It used to be a bare canvas with a top chip.
- **The putt state joined the skeleton** — the ◄/► that cycle clubs while aiming now nudge the aim;
  the break read moved to the read row (it was ellipsising in the adjuster label).
- **Tap-to-swing** — the aim state's commit button fires the previewed shot through the pull
  gesture's own dispatch. One path, no new mechanic; makes the screen one-handed.
- **The caddy badge is the caddy everywhere.** `playView` takes a measured `caddyAnchor`
  (`{muzzle, head}`) and skips its corner figure, so a guard's laser fires off the framed portrait
  instead of a figure that only existed during flight. Slot dims when the caddy has no read here;
  reserves its box when none is hired.
- **Info bar stops reflowing** — min-width'd distance slot, score chips on their own row. Aim and
  watch are line-for-line identical.
- **Readouts up a step** throughout (stats 13→14.5, sub-line 11.5→12.5, legend 11.5→12.5, club name
  15→16.5, lie/score chips, power label).

## Bug found while measuring

The info bar was reading `play.lie` during the shot animation — which is **already** the lie the ball
will finish in. It was spoiling the result before the ball landed. The watch state now shows the lie
the shot was played FROM (`shot.lieFrom`).

## Verified

- `npm run check` green: typecheck, **164 files / 1869 tests**, build.
- New `tests/play-hud-frame.test.ts` — pure structural half (regions × three shapes, nav button
  count, the caddy slot's three cases) + a real-Chromium half against the BUILT artifact: mount the
  play screen, tap Swing, assert every region survives the transition **within 2px**, that dead
  controls are `disabled` not gone, and that no chrome blankets the map. Plus a source check that no
  branch hand-rolls the frame element any more.
- Eyes-on: aim / watch / putt / putt-aim captured at 412×915 (Pixel-class) and read back; the forced
  guard-redirect demo (`_gsFeel.forceRedirect='laser'`) re-checked end to end — badge in the slot,
  spark burst on the intercept, speech bubble clear of the controls panel, zero page errors.

## Not verified / needs a human

- **Real-device feel.** Whether the bigger panel occludes too much map in play, and whether the
  putt panel's taller top edge reads as movement. Both are eyes-on-play judgements.
- **Landscape / tablet.** No pass; the frame is phone-portrait tuned.
